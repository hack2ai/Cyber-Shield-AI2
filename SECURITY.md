# Security Policy

## Supported versions

Security fixes are developed against the `main` branch. Older commits and unpublished branches are not considered supported releases.

## Reporting a vulnerability

Please do not open a public GitHub issue for a suspected security vulnerability.

Instead, use GitHub's private vulnerability reporting/security advisory flow for this repository when available. Include:

- A clear description of the vulnerability.
- The affected component, endpoint, workflow, or dependency.
- Reproduction steps or a minimal proof of concept.
- The potential security impact.
- Any suggested mitigation, if known.

Please avoid sending real credentials, API keys, personal data, or live third-party targets in a report.

## Response expectations

Security reports are triaged as soon as practical. Valid reports may result in a private fix, dependency update, configuration change, or coordinated disclosure.

## Scope

Security issues in the application, Express API, browser extension, CI/CD workflows, dependency configuration, and repository security controls are in scope.

The project is intended for defensive security analysis. Reports involving third-party systems should use owned or explicitly authorized targets.

## Safe-harbor expectation

Good-faith security research performed without accessing, modifying, or disrupting data belonging to others is welcomed. Please stop testing once you have enough evidence to demonstrate the issue and report it privately.
